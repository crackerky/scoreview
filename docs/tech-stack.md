# 技術スタック選定

## 採用技術

| 領域 | 採用 | 版 | 理由 |
|---|---|---|---|
| 閲覧ページと管理画面 | Next.js(App Router)+ TypeScript | 16.4 / TS 7.0 | サーバー側で HTML を組み立てて返せるので、参照サイトと同じく JavaScript なしで全情報が読める。管理画面のフォームは Server Actions で Go API へ中継できる |
| API とドメインロジック | Go(標準 `net/http`) | 1.25 | 発注側の希望。順位計算や取込ツールのような計算と I/O の多い処理を型付きで書ける。Go 1.22 以降の `ServeMux` はメソッドとパス変数を扱えるので、ルーターのライブラリを足さない |
| ORM | GORM + pgx ドライバ | gorm 1.31 | Go で最も利用者の多い ORM で、引き継ぎやすい。条件はプレースホルダで渡るので SQL インジェクションを防げる |
| マイグレーション | goose(SQL ファイル) | 3.29 | スキーマを SQL で書いて差分を読めるようにする。GORM の AutoMigrate は使わない(本番スキーマがコードの構造体から暗黙に変わるのを避けるため) |
| DB | PostgreSQL | 17 | JSONB(ブラケット表の格子を保存)と部分インデックスを使う |
| 開発とテストの DB | embedded-postgres | 1.34 | Docker なしで本物の PostgreSQL を起動できる。この開発機(WSL2)で 17.5 の起動を確認済み |
| HTML の無害化 | bluemonday | (実装時に固定) | 自由記述欄のインライン style を残しつつ script と危険な属性を落とせる |
| パスワード | argon2id(`golang.org/x/crypto`) | 0.58 | OWASP のパスワード保存の推奨方式 |
| 取込ツールの HTML 解析 | goquery | 1.13 | CSS セレクタで参照サイトの表を読める |
| デプロイ | Vercel Services | ― | Next.js と Go を 1 プロジェクトで同時にデプロイし、プレビュー環境でも両者の版がずれない |
| 本番 DB | Neon(Vercel Marketplace 経由) | ― | Vercel の環境変数に接続文字列が自動で入る。料金は要確認 |
| lint と整形(TS) | Biome | 2.5 | ESLint と Prettier を 1 ツールにまとめる |
| lint(Go) | golangci-lint(gosec、forbidigo を含む) | 実装時に固定 | gosec が SQL 文字列の組み立て(G201、G202)を検出し、forbidigo で GORM の `Raw` と `Exec` の使用を禁止する |
| テスト(TS) | Node 標準テストランナー + tsx | ― | 設定ファイルと依存を増やさない |
| テスト(Go) | `testing` + testify | 1.12 | 同上 |
| 画面比較 | Playwright | 1.64 | 参照サイトと本サイトのスクリーンショットを同じ ID で撮って比べる |

## 代替案との比較

### バックエンドを Go にするか、Next.js の Route Handler に寄せるか

Next.js だけでも API は書ける。
それでも Go を分けるのは、取込ツール(長時間のバッチ)と順位計算をサーバーレスの関数実行時間に縛られない形で持ちたいからである。
取込ツールは Go のコマンドとして手元や CI で動かし、同じドメインコードを API サーバーからも使う。

### ORM の比較

| 候補 | 判断 | 理由 |
|---|---|---|
| GORM | 採用 | 利用者と資料が多い。SQL マイグレーションと併用できる |
| ent | 不採用 | 型は強いが、スキーマの主導権が ent のコード側に移り、SQL マイグレーションと二重管理になる |
| Bun | 不採用 | SQL に近く相性はよいが、利用者が GORM より少ない |
| sqlc | 不採用 | 安全だが ORM ではなく、発注側の「ORM を使う」という方針に合わない |

GORM には生 SQL を渡す `Raw` と `Exec` がある。
これを許すと文字列連結による SQL インジェクションの余地が残るので、マイグレーション以外では lint で禁止する。

### ルーター

chi や Echo は使わない。
Go 1.22 以降の `http.ServeMux` が `GET /api/v1/teams/{id}` の形を解釈でき、必要なミドルウェア(内部トークン検証、ログ、パニック回復)は数十行で書けるためである。

### 参照サイトの CSS と画像をそのまま使うか

使わない。
CSS は調査で得た値(色、幅、余白、クラス名)をもとに書き直し、ロゴやヘッダー画像は仮の素材に置き換える。
参照サイトの運営会社のブランド素材をそのまま公開すると、その会社のサイトだと誤認させるためである。
色と素材はブランド設定に集めてあり、自社ブランドへの差し替えはそこだけで済む([architecture.md](architecture.md) の可変点)。

## ランニングコスト

料金は 2026 年 10 月時点で未確認であり、契約前に Vercel と Neon の料金ページで確かめる。
本サイトの負荷の前提は次のとおり。

- 大会当日のアクセスは数百人規模で、スケジュールと試合ページの再読込が中心になる。
- 閲覧ページは DB の読み取りだけで、1 ページあたり 1〜3 回の問い合わせで返す。

コストを抑える制御点は次の 2 つである。

- 終了した大会のページは内容が変わらないので、Next.js のキャッシュ(大会の状態が「終了」のときだけ長い期限)で DB への問い合わせを減らせる。
- 試合中の大会だけ短い期限にする。参照サイトにも自動更新はなく、利用者が更新ボタンを押す方式なので、短い期限で十分である。
