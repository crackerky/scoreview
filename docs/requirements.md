# 要件定義書

## 背景と目的

score.clubjr.com(以下「参照サイト」)は、アルティメットを中心としたフライングディスク競技の大会スコア速報サイトである。
2017 年から 2027 年までの大会 348 件を掲載し、大会ごとに日程、順位、グループ成績、チーム、試合経過、選手成績を公開している。

本プロジェクトは、参照サイトの情報構造と画面遷移と見た目を高い精度で再現したスコアサイトを作り、それを土台に自社仕様へ作り変える。
最初に模倣を徹底する理由は、参照サイトが十年近い運用で積み上げた「大会運営者と観戦者が実際に必要とした情報の並べ方」をそのまま手に入れるためである。
自社仕様への変更は、模倣版が完成してから差分として加える。

参照サイトの調査結果は [clone-spec/](clone-spec/README.md) にある。
本書の機能要件は、この調査で実際の HTML から確認した事実を根拠にしている。

## 想定ユーザー

- **観戦者**：大会の日程、試合結果、順位を見る。会場でスマートフォンから見ることが多い。
- **出場チームと選手**：自チームの次の試合、相手、個人成績を見る。
- **大会運営者**：大会、ディビジョン、グループ、チーム、試合を登録し、試合のスコアと経過を入力する。
- **記録係**：担当試合のスコアと得点経過だけを入力する。

## フェーズ分割

| フェーズ | 範囲 | 完了条件 |
|---|---|---|
| 1(MVP) | 参照サイトで見える全ページの模倣、日英切替、管理画面(大会の登録とスコア入力)、参照サイトからの取込ツール | 代表 16 大会を取り込み、全ページ種別で参照サイトと見比べて構造と表示内容が一致する |
| 1b | 大会運営の自動化([format-engine.md](format-engine.md)、[operations/operator-experience.md](operations/operator-experience.md)):形のテンプレート、タイブレーク設定、勝ち上がりと順位決定戦の自動生成、確定と自動進行、時間割の生成、本部ダッシュボード | 運営会社がよく使う 3 テンプレートで、チーム登録から最終順位まで手作業の転記なしに大会を回せる |
| 2 | 自社仕様への作り変え(ブランド、配色、スマートフォン向けレイアウト、画像アップロード、SOTG 入力) | フェーズ 2 着手時に別途定義する |
| 3 | LINE 連携(公式アカウントからの試合通知、LINE ログイン、参加者によるスコア入力) | [line-integration.md](line-integration.md) を着手時に要件化する |

フェーズ 1 と 2 の実装は、LINE 連携で作り直しが起きないように [line-integration.md](line-integration.md) の「フェーズ 1 から守る構造」に従う。

フェーズ 1 では、参照サイトに見た目の欠陥があっても再現する(列幅の 100% 超過、見出しのはみ出しなど)。
ただし、利用者の安全や運用に関わる挙動は再現しない。
再現しない挙動は「意図的な差分」節に列挙する。

## 機能要件

### 閲覧ページ(フェーズ 1)

URL は参照サイトと同じパス体系にする(`/sctnmt`、`/scview/{大会ID}`、`/pscore/scv_*/open/{ID}`)。
同じ ID で参照サイトと本サイトを並べて比較できるようにするためである。
全ページは `?lang=jp|en` で表示言語を切り替え、ページ内のリンクは現在の言語を引き継ぐ。

- **F-01 大会一覧**(`/sctnmt`)：「エントリー受付中」「エントリー締切り」「大会終了」の区分ごとに、開催日の新しい順に大会を並べる。一覧に載せない設定の大会は、URL を直接開けば表示する。
- **F-02 大会トップ**(`/scview/{ID}` と `/pscore/scv_top/open/{ID}`)：大会名、ロゴ、開催ディビジョン表、自由記述欄を表示する。ディビジョン表の [スケジュール] と [最終順位] は、データの有無に応じてリンクか灰色の文字になる。
- **F-03 大会ナビ**：大会に属する全ページの上部に、大会トップ、チーム一覧、スケジュール、ディビジョン成績、グループ成績、ギャラリーのドロップダウンを出す。項目の有無とラベルは大会ごとに変わる(7 パターン、[E 章 3](clone-spec/E-catalog-variants.md))。
- **F-04 サイドバー**：大会ごとのバナー画像を 0〜30 枚並べる。
- **F-05 チーム一覧**：ディビジョンごとに見出しと件数を出し、チームを 3 列で並べる。個人戦ではリンクのない選手名と「Players」を出す。
- **F-06 スケジュール**(大会全体とディビジョン別)：日付、チーム、コートで絞り込み、列見出しで昇順と降順を切り替える。試合の状態(未試合、試合中、終了)を行の色で示し、未確定の対戦相手を「[A1-勝ち]」の形で出す。
- **F-07 ディビジョン成績**：順位表、得点ランキング、ブロックランキングを出す。順位は順位決定戦の結果から決まる値であり、勝率から計算しない。
- **F-08 グループ成績**：総当たり型(対戦表、リーグ結果、結果一覧)、トーナメント型(罫線で描くブラケット表と結果一覧)、画像のみの型の 3 種を出し分ける。
- **F-09 チーム**：チーム成績、対戦一覧、選手一覧、スタッフ一覧を出す。ディスクゴルフ団体戦では選手一覧だけを出す。
- **F-10 試合**：スコアボード、得点経過(新しい順)、出場選手、統計を出す。5 秒間は更新ボタンを押せない。
- **F-11 選手**：個人成績、本人が関わった得点の一覧、同じチームの前後の選手へのリンクを出す。
- **F-12 ギャラリー**：写真のサムネイルを並べ、クリックで拡大表示し、前後の写真へ移動できる。
- **F-13 存在しない ID**：参照サイトと同じ文面のエラー画面を出す。

各ページの構造、文言、条件分岐の詳細は clone-spec の各章を仕様とする。

### 管理画面(フェーズ 1)

参照サイトの管理画面は公開されていないため、閲覧ページのデータを過不足なく入力できることを基準に本プロジェクトで設計する。

- **A-01 ログイン**：メールアドレスとパスワードでログインする。
- **A-02 大会の登録**：大会の基本情報、ロゴ、自由記述(日英)、区分、一覧への掲載、ナビのラベル種別、バナーを編集する。
- **A-03 構成の登録**：ディビジョン、グループ(総当たり、トーナメント、画像)、チーム、選手、スタッフを登録する。
- **A-04 試合の登録**：日付、時刻、コート、試合コード、対戦チーム(未確定なら「A1 の勝者」のような参照)を登録する。
- **A-05 スコア入力**：得点(得点者、アシスト)、タイムアウト、プル、試合終了を時刻つきで記録し、スコアと状態を更新する。試合ごとのブロック数を記録する。
- **A-06 順位の確定**：ディビジョンの最終順位を登録し、[最終順位] を公開する。
- **A-07 ギャラリー**：ギャラリーと写真の URL を登録する。

### 取込ツール(フェーズ 1)

- **I-01**：大会 ID を指定して、参照サイトの大会トップ、チーム一覧、日程、グループ、チーム、試合の各ページを読み、本サイトの DB に同じ ID で登録する。
- **I-02**：参照サイトへのリクエスト間隔を 1 秒以上空ける。取得済みのページはローカルに保存し、再実行で取り直さない。
- **I-03**：取り込んだデータは開発用 DB にだけ入れる。実在の選手名を含むため、公開環境には入れない。公開環境には架空データを生成するシード機能で入れる。

## 非機能要件

- **表示の再現度**：代表 14 大会の全ページ種別で、参照サイトとのスクリーンショット比較を行い、差分を一覧にして説明できる状態にする。
- **性能**：一覧と各ページの表示を、サーバー側で 1 秒以内に返す(取込済み最大規模の大会、日程 282 試合で計測)。
- **セキュリティ**：DB への問い合わせは ORM のパラメータ渡しだけで行い、SQL 文字列を連結しない。自由記述 HTML はサーバー側で許可リスト方式の無害化を通してから出す。Go API はインターネットに公開せず、Next.js サーバーからだけ呼ぶ。
- **デプロイ**：Vercel の 1 プロジェクトで、Next.js と Go を同時にデプロイする。
- **言語**：日本語と英語。英語名が未登録の項目は、参照サイトと同じく空で表示する。

## 権限モデル

| 役割 | できること |
|---|---|
| 未ログイン | 閲覧ページの全て |
| 記録係(staff) | 割り当てられた大会の試合のスコア入力 |
| 管理者(admin) | 全大会の登録、編集、削除、ユーザー管理 |

## 意図的な差分

参照サイトの挙動のうち、次のものは再現しない。

| 参照サイト | 本サイト | 理由 |
|---|---|---|
| 存在しない ID に HTTP 500 を返す | 同じ文面の画面を HTTP 404 で返す | 500 は監視でサーバー障害と区別できない |
| リンクが `href="#"` と onclick による遷移 | 通常の `href` | JavaScript なしで遷移でき、検索エンジンと支援技術が辿れる |
| スケジュールの絞り込みとソートを POST で送る | 同じ値を GET のクエリで送る | 絞り込み結果の URL を共有できる。画面上の挙動は同じ |
| 自由記述 HTML をそのまま出力 | 許可リストで無害化して出力 | 管理者アカウントが乗っ取られた場合のスクリプト注入を防ぐ |
| 名前(英語版では英語名)の空のグループへのナビのリンクに、リンク先の絶対 URL(`https://score.clubjr.com/...`)を文字として出す | リンク先のルート相対パスを文字として出す | 欠陥の見た目は再現するが、リンクと同じくホストに依存しない形にする |
| ロゴ、ヘッダー画像、SNS リンクが参照サイト運営会社のもの | ブランド設定ファイルの値(初期値は仮のもの) | 他社のブランドを名乗るサイトを公開しない。自社ブランドへの差し替え点にもなる |
| 印刷用の CSS が無い(画面のまま印刷され、ナビとサイドバーが入る) | 印刷のときだけナビ、サイドバー、フッター、更新ボタンを消し、本文を A4 縦に収める(`apps/web/src/styles/print.css`)。画面の見た目は変えない | 日程、グループ、ディビジョン成績を会場に貼る運用のため(docs/operations/operator-experience.md「紙を上回ることが前提」) |

## スコープ外

- 大会へのエントリー受付(参照サイトでも別サイトで行っている)
- SOTG(スピリット)スコアの入力。参照サイトでは 2017 年と 2020 年前後の大会にだけ表示があり、フェーズ 2 で扱う
- ガッツ競技の試合画面(参照サイトの CSS に痕跡があるが、348 大会に該当データがない)
- ディスクゴルフのストローク数とフリースタイルの審査得点(参照サイトにも表示がなく、結果は自由記述欄の文章で示している)
- 大会をまたぐ通算成績(参照サイトにも存在しない)
